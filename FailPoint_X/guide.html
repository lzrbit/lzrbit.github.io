Code and data

The benchmark code on GitHub includes the offline scorer, recorded example, simulation clients and post-training code. The training dataset on Hugging Face contains 2,320 accepted takeover trajectories in LeRobot format. A link to the dataset is not yet available. The dataset explorer shows the task-level counts, including the 80 recoveries reserved for development.

Score the recorded example

From a checkout of the benchmark repository, run the following command with Python 3.9 or later. The scorer uses the Python standard library and the recorded Base-restart outcomes included in the repository.

python3 -m failpoint_x score \
  --recovery examples/base_restart/rec.jsonl \
  --nominal examples/base_restart/norm.jsonl

The example covers 1,152 recovery rollouts and 500 scheduled nominal starts. Expected recovery success is 22.2% on L1–L3 and 7.6% on L4–L5. Across valid nominal starts, expected success is 43.9% within 1,200 steps and 33.6% within the task-specific 1.1T deadline.

Evaluate a policy from nominal starts

The simulator uses Python 3.10.16. The benchmark repository lists its tested dependency versions in eval/constraints.txt.

Install LIBERO-X at revision f528726, MuJoCo 2.3.0, robosuite 1.4.0 and the OpenPI client. Configure EGL and LIBERO_CONFIG_PATH. The LIBERO-X checkout must include the BDDL tasks and libero/libero_x/LEVEL5/L5-*.jsonl instruction files. Start your OpenPI-compatible policy server and run this command from the benchmark root.

python3 -m failpoint_x run --track nominal --liberox /path/to/LIBERO-X \
  --output results/my_policy --tag my_policy --host 127.0.0.1 --port 8000

Add --dry-run to preview the command before starting the simulator. This track uses the nominal start schedule included in the benchmark repository.

Evaluate recovery from recorded failures

The benchmark repository provides the recovery evaluator and its manifest. The recorded simulator states required to run this track are not included in the repository. If you have those files, place them at the paths in eval/test_bundle/test_manifest.json under eval/test_bundle/rollouts/. After running the nominal track above, use the same policy checkpoint and server settings to evaluate recovery and score both tracks.

python3 -m failpoint_x run --track recovery --liberox /path/to/LIBERO-X \
  --output results/my_policy --tag my_policy --host 127.0.0.1 --port 8000
python3 -m failpoint_x score \
  --recovery results/my_policy/rec.shard*.jsonl \
  --nominal results/my_policy/norm.shard*.jsonl

Keep the generated .identity.json files beside the result shards so the scorer can compare the policy identities. Compare the reported checkpoints.
